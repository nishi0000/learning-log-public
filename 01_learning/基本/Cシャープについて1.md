-  トピック：`List<int>` はC#側で定義してる型か？
    
    - 何を扱った：
        
        - `List<int>` の正体（`List<T>` の具体化）
            
        - 「C#言語」そのものが持つ型というより「.NET標準ライブラリ（BCL）が提供する型」
            
    - 結論：
        
        - `List<T>` は .NET（標準ライブラリ）が提供するジェネリック型
            
        - `List<int>` は `T=int` を当てはめた具体化
            
    - 覚えるもの：
        
        - `List<T>`：ジェネリック型（標準ライブラリ）
            
        - `List<int>`：`T=int` の具体化
            
-  トピック：値型と参照型の理解の確認（ユーザーの例）
    
    - 何を扱った：
        
        - ユーザーの理解：
            
            - 値型：代入で値がコピーされる（`int a=123; c=a; c=321;` → `a`は変わらない）
                
            - 参照型：場所がコピーされるので、片方変更で他方も変わるイメージ
                
        - 例として `string` を挙げたが、期待した挙動（`c=b; c="うえお";` で `b` も変わる）は成立しない点
            
    - 結論：
        
        - `string` は参照型だが **immutable（不変）**
            
            - `c = "うえお"` は「同じ実体の中身を書き換え」ではなく「`c` の参照先を付け替え」
                
            - そのため `b` は変わらない
                
        - 「参照型で元も変わる」のは、同じ実体に対して **中身を書き換える操作** をした場合（例：`List<int>.Add(...)`）
            
    - 覚えるもの：
        
        - 参照型でも **代入（参照の付け替え）** と **ミューテーション（中身変更）** は別
            
        - `string`：参照型だが immutable（不変）
            
        - `List<T>`：中身を変更できる参照型（同じ実体を共有すると変更が波及する）
