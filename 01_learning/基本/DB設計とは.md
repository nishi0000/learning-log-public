### 1. 扱ったトピック一覧（時系列）

-  トピック：DBの論理設計と物理設計の違い
    
    - 何を扱った：DB設計における「論理設計」と「物理設計」の役割の違い
        
    - 結論：
        
        - 論理設計：業務として必要なデータと関係を決める（DB製品に依存しにくい）
            
        - 物理設計：特定DB上での実装（型・インデックス・配置・運用など）を決める（DB製品・運用に依存）
            
        - 論理設計の例要素：エンティティ、属性、関係、主キー/外部キー、正規化
            
        - 物理設計の例要素：データ型の確定、インデックス、パーティション、制約の実装、運用（バックアップ等）
            
    - 覚えるもの：
        
        - 「論理＝何のデータをどう管理するか（関係・ルール）」
            
        - 「物理＝特定DBでどう置いて速く安全に運用するか（型・索引・運用）」
            
-  トピック：DDL
    
    - 何を扱った：DDLとは何か（SQLの分類）
        
    - 結論：
        
        - DDL：Data Definition Language（データ定義言語）
            
        - DBの構造（入れ物）を定義・変更するSQLの種類
            
        - 代表コマンド：CREATE / ALTER / DROP / TRUNCATE（DDL寄り）
            
        - 例として `CREATE TABLE users (...)` を提示
            
        - 参考としてDML（INSERT/UPDATE/DELETE/SELECT）との役割分担に触れた
            
    - 覚えるもの：
        
        - DDL → Data Definition Language → データ定義言語 → 「テーブル等の構造を作る/変える/消す」
            
        - 代表コマンド：CREATE / ALTER / DROP（＋TRUNCATEはDDL寄り）
