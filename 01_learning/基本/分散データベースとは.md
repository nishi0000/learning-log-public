### 1. 扱ったトピック一覧（時系列）

-  トピック：分散データベースとは何か
    
    - 何を扱った：
        
        - 「分散データベースってなんですか？」という質問
            
        - 1台のサーバーにまとめて持つDBとの違い
            
    - 結論：
        
        - 分散データベース = 1つのデータベースを、1台ではなく複数のコンピュータに分けて持つ仕組み
            
        - 利用者からは1つのDBのように見える形をとることがある
            
        - 普通のデータベースのイメージ = 1台のサーバーにデータがまとまって入っている形
            
        - 分散データベースのイメージ = データを複数のサーバーに分散して保存・処理する形
            
    - 覚えるもの：
        
        - 分散データベース = 複数サーバーにまたがってデータを保存・管理するDB
            
        - 通常DBとの対比
            
            - 通常DB：1台に集約
                
            - 分散DB：複数台に分散
                
-  トピック：分散する目的
    
    - 何を扱った：
        
        - なぜデータを複数サーバーに分けるのか
            
    - 結論：
        
        - 負荷を分散するため
            
        - 障害に強くするため
            
        - 大量データを扱いやすくするため
            
        - 地理的に近い場所で処理して速くするため
            
    - 覚えるもの：
        
        - 分散する主目的
            
            - 負荷分散
                
            - 耐障害性
                
            - スケール対応
                
            - 地理的近接による性能向上
                
-  トピック：データの分け方 その1
    
    - 何を扱った：
        
        - データを分割して持つ方式
            
    - 結論：
        
        - サーバーごとに異なる一部のデータを持つ方式
            
        - このやり方をシャーディングと呼ぶことがある
            
        - 例：
            
            - 1〜1000番の顧客 → サーバーA
                
            - 1001〜2000番の顧客 → サーバーB
                
    - 覚えるもの：
        
        - シャーディング = データを分割して別々のサーバーに持たせる方式
            
-  トピック：データの分け方 その2
    
    - 何を扱った：
        
        - 同じデータを複数サーバーに持つ方式
            
    - 結論：
        
        - 同じ内容を複数のサーバーにコピーして持つ方式
            
        - このやり方をレプリケーションと呼ぶ
            
        - 例：
            
            - サーバーAとサーバーBの両方に同じ注文データを持つ
                
    - 覚えるもの：
        
        - レプリケーション = 同じデータを複製して複数サーバーに持たせる方式
            
-  トピック：分散データベースの利点
    
    - 何を扱った：
        
        - 分散DBのメリット
            
    - 結論：
        
        - 性能を上げやすい
            
        - 障害に強くしやすい
            
        - 大規模サービスで使いやすい
            
    - 覚えるもの：
        
        - メリット3点
            
            - 性能
                
            - 障害耐性
                
            - 大規模運用
                
-  トピック：分散データベースの難しさ
    
    - 何を扱った：
        
        - 分散DBの設計・運用上の注意点
            
    - 結論：
        
        - データの整合性を保つのが難しい
            
            - 例：Aは更新されたがBはまだ、という状態が起こりうる
                
        - 設計や運用が複雑になる
            
        - 通信遅延や障害時の制御が難しい
            
    - 覚えるもの：
        
        - 難所3点
            
            - 整合性
                
            - 複雑性
                
            - 通信・障害制御

        - 最後に一言でどう表現するか
            
    - 結論：

            - 分散データベース

            - 難しさは整合性
