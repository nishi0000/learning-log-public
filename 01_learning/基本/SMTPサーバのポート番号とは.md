-  トピック：SMTPサーバ
    
    - 何を扱った：
        
        - SMTPサーバとは何か。
            
        - メール送信時に使うサーバの役割。
            
    - 結論：
        
        - SMTPサーバは、メールを送信するためのサーバ。
            
        - メールを出すときに使う郵便局のようなもの。
            
        - メール送信の流れは以下。
            
            - 自分のPC・スマホ
                
            - SMTPサーバ
                
            - 相手側のメールサーバ
                
            - 相手のメールボックス
                
    - 覚えるもの：
        
        - SMTP = メール送信
            
        - POP3 / IMAP = メール受信
            
        - SMTPサーバ = メール送信用のサーバ

    - 結論：
        
        - SMTP → Simple Mail Transfer Protocol → エスエムティーピー → メールを送信・転送するための通信ルール。
            
    - 覚えるもの：
        
        - SMTP = Simple Mail Transfer Protocol
            
        - SMTP = メール送信・転送の通信ルール

    - 覚えるもの：

            - 相手のメールサーバへ転送する

    - 結論：
        
        - SMTPはメール送信。

    - 覚えるもの：

        - IMAP = 受信・サーバ上で管理

-  トピック：SMTPのポート番号
    
    - 何を扱った：
        
        - SMTPにはデフォルトのポート番号があるのか。
            
        - ここでいうポート番号はSMTPサーバの送信用ポート番号なのか。
            
    - 結論：
        
        - SMTPでよく出てくるポート番号は、25番、587番、465番。
            
        - ここでいうポート番号は、SMTPサーバがメール送信用の接続を受け付けている受付番号のこと。
            
        - 「SMTPサーバの送信用ポート番号」という理解で大きく問題ない。
            
    - 覚えるもの：
        
        - SMTP = 25番
            
        - メールソフトからSMTPサーバへの送信では587番がよく使われる
            
        - 465番はSSL/TLSで暗号化したSMTP送信で使われることがある

-  トピック：宛先ポート番号
    
    - 何を扱った：
        
        - 宛先ポート番号とは何か。
            
    - 結論：
        
        - 宛先ポート番号は、通信を受け取る側のコンピュータで、どのサービス・アプリに届けるかを示す番号。
            
        - SMTPなら、宛先ポート番号は25番や587番になる。
            
        - IPアドレスは「どのサーバに届けるか」。
            
        - ポート番号は「そのサーバのどの受付口に届けるか」。
            
    - 覚えるもの：
        
        - 宛先IPアドレス = どのサーバに届けるか
            
        - 宛先ポート番号 = そのサーバのどのサービス・受付口に届けるか

-  トピック：送信元ポート番号
    
    - 何を扱った：
        
        - 宛先ポート番号の逆は何か。
            
    - 結論：
        
        - 宛先ポート番号の逆は、送信元ポート番号。
            
        - 宛先ポート番号は、相手側のどのサービスに届けるかを示す。
            
        - 送信元ポート番号は、自分側のどの通信に返事を返してもらうかを示す。
            
        - 送信元ポート番号は、PC側が一時的に自動で割り当てる番号であることが多い。
            
    - 覚えるもの：
        
        - 宛先ポート番号 = 相手側のサービス番号
            
        - 送信元ポート番号 = 自分側の返信用番号
            
        - 送信元ポート番号は固定ではないことが多い

-  トピック：ウェルノウンポート
    
    - 何を扱った：
        
        - ウェルノウンポートとは何か。
            
    - 結論：
        
        - ウェルノウンポートは、よく使われるサービスのために、あらかじめ決められているポート番号。

    - 覚えるもの：
        
        - Well-known ports → ウェルノウンポート → よく知られているポート番号
            
        - 0〜1023番 = ウェルノウンポート
            
        - 代表的なサービス用に予約されている有名なポート番号

-  トピック：同じWebサーバ上の複数HTTPSサイト
    
    - 何を扱った：
        
        - 同じWebサーバ上に、HTTPS通信するサイトが2つある場合、両方443番にできるのか。
            
    - 結論：
        
        - 同じWebサーバ上にHTTPSサイトが2つあっても、両方443番で運用できる。
            
        - 通信先はポート番号だけで決まるわけではない。
            
        - 通常は、IPアドレス + ポート番号 + ホスト名 で区別できる。
            
        - Webサーバはリクエストに含まれるホスト名を見て、返すサイトを振り分ける。
            
    - 覚えるもの：
        
        - 複数HTTPSサイトでも443番を共用できる
            
        - 区別にはホスト名を使う
            
        - 「同じ443を使いながら、ホスト名で振り分ける」

-  トピック：SNI
    
    - 何を扱った：
        
        - HTTPSで同じIPアドレス・同じ443番ポートでも、証明書を出し分ける仕組み。
            
    - 結論：
        
        - HTTPSは暗号化があるため、サーバ証明書の扱いが関係する。
            
        - SNIにより、同じIPアドレス・同じ443番ポートでも、ホスト名ごとに適切な証明書を出し分けられる。
            
    - 覚えるもの：
        
        - SNI = HTTPSでホスト名ごとに証明書を出し分ける仕組み
            
        - 同一IP + 443番でも、HTTPSサイトを複数運用できる理由の一つ
            

---

-  トピック：同じIP・同じポートでできないパターン
    
    - 何を扱った：
        
        - 同じサーバで複数プロセスが同じポートを使えるか。
            
    - 結論：
        
        - 同じIPアドレス、同じポート番号、同じホスト名で、まったく別の2つのWebサーバプロセスを同時に待ち受けさせることは基本できない。
            
        - 例：
            
            - Apacheが0.0.0.0:443を使用中
                
            - Nginxも0.0.0.0:443を使用したい
                
            - この場合はポートの取り合いになる。
                
    - 覚えるもの：
        
        - 同じIP + 同じポート + 同じホスト名を、別プロセスで同時に待ち受けるのは基本不可
            
        - 複数サイト運用は「同じ443を使いながらホスト名で振り分ける」仕組みで実現する
