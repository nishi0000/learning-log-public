### 1. 扱ったトピック一覧（時系列）

-  トピック：DNSリフレクション攻撃
    
    - 何を扱った：
        
        - 「DNSリフレクションてなに？」という質問
            
        - DNSサーバを“反射板”として悪用する攻撃
            
    - 結論：
        
        - DNSリフレクション攻撃とは、DNSサーバを経由して攻撃対象に大量のDNS応答を送らせる攻撃。
            
        - reflection = 反射。
            
        - 攻撃者は、送信元IPアドレスを攻撃対象のIPアドレスに偽装してDNS問い合わせを送る。
            
        - DNSサーバは、偽装された送信元IPアドレスにDNS応答を返す。
            
        - その結果、攻撃対象にはDNSサーバから大量の応答が届く。
            
    - 覚えるもの：
        
        - DNSリフレクション = DNSサーバを反射板にして、攻撃対象へDNS応答を飛ばす攻撃。
            
        - 試験向け表現：
            
            - 送信元IPアドレスを攻撃対象に偽装したDNS問い合わせを多数のDNSサーバへ送り、DNS応答を攻撃対象に集中させるDDoS攻撃。

-  トピック：DNSリフレクション攻撃の通信の流れ
    
    - 何を扱った：
        
        - 攻撃者、DNSサーバ、攻撃対象の関係
            
    - 結論：
        
        - 流れは以下の通り。
            
            ```text
            ① 攻撃者がDNSサーバに問い合わせる
               ※送信元IPを「攻撃対象」に偽装する
            
            攻撃者
              ──偽装DNS問い合わせ──▶ DNSサーバ
              送信元IP：攻撃対象
            
            
            ② DNSサーバは、偽装された送信元に回答を返す
            
            DNSサーバ
              ──DNS応答──▶ 攻撃対象
            ```
            
        - 攻撃対象から見ると、いろいろなDNSサーバから大量に返事が来る状態になる。
            
    - 覚えるもの：
        
        - 攻撃者が直接攻撃対象に送るのではなく、DNSサーバを経由して攻撃対象に通信を返させる。
            
        - 攻撃対象からは、通信元がDNSサーバに見える。

    - 何を扱った：
        
        - DNSリフレクション攻撃で何が怖いのか
            
    - 結論：
        
        - 攻撃者の身元が隠れやすい。
            
        - 攻撃対象から見ると、攻撃者本人ではなくDNSサーバから通信が来ているように見える。
            
        - DNS応答は問い合わせより大きくなることがあり、通信量を増幅できる。
            
    - 覚えるもの：
        
        - DNSリフレクション攻撃は、攻撃者が隠れやすい。
            
        - DNSサーバを踏み台・反射板のように使う。

-  トピック：DNSアンプ攻撃
    
    - 何を扱った：
        
        - 「DNSアンプ攻撃・・・とかってなに？」という質問
            
    - 結論：
        
        - DNSアンプ攻撃とは、DNSを使って通信量を増幅して攻撃対象にぶつける攻撃。
            
        - アンプは amplification の略。
            
        - amplification = 増幅。
            
        - 小さいDNS問い合わせを送って、大きいDNS応答を攻撃対象に返させる。
            
    - 覚えるもの：
        
        - DNSアンプ攻撃 = DNSを使った増幅攻撃。
            
        - 小さい問い合わせを、大きいDNS応答にして、攻撃対象にぶつける攻撃。

-  トピック：DNSアンプ攻撃の通信の流れ
    
    - 何を扱った：
        
        - DNSアンプ攻撃の基本構造
            
    - 結論：
        
        - 攻撃者はDNSサーバに問い合わせを送る。
            
        - このとき、送信元IPアドレスを攻撃対象のIPアドレスに偽装する。
            
        - DNSサーバは問い合わせの送信元に応答を返す。
            
        - 送信元IPが攻撃対象に偽装されているため、DNS応答は攻撃対象へ届く。
            
            ```text

            DNSサーバ
              ↓ 大きなDNS応答
            攻撃対象
            ```
            
    - 覚えるもの：
        
        - 送信元IPを攻撃対象に偽装する。
            
        - DNSサーバからの大きな応答を攻撃対象に集中させる。

-  トピック：DNSリフレクション攻撃とDNSアンプ攻撃の関係
    
    - 何を扱った：
        
        - 「リフレクション」と「アンプ」の違い
            
    - 結論：
        
        - DNSリフレクション攻撃は、DNSサーバを反射板にする攻撃。
            
        - DNSアンプ攻撃は、DNSサーバを使って通信量を増幅する攻撃。
            
        - 実際にはセットで使われることが多い。
            
        - DNSサーバを反射板にしつつ、応答を大きくして攻撃対象に浴びせる形になる。
            
    - 覚えるもの：
        
        ```text
        DNSリフレクション攻撃
        = DNSサーバを反射板にする攻撃
        
        DNSアンプ攻撃
        = DNSサーバを使って通信量を増幅する攻撃
        ```
        
        - 試験では、DNSリフレクション攻撃はDNSアンプ攻撃系のDDoS攻撃としてつなげて覚える。

-  トピック：DNSアンプ攻撃で増幅できる理由
    
    - 何を扱った：
        
        - なぜ「小さい問い合わせ」が「大きい応答」になるのか
            
    - 結論：
        
        - DNSでは、問い合わせより応答の方が大きくなることがある。
            
        - 例：
            
            ```text
            問い合わせ：
            「この名前について教えて」
            
            応答：
            「IPアドレスはこれで、関連情報はこれで、署名情報はこれで……」
            ```
            
        - DNSSECなどで応答データが大きい場合、増幅効果が大きくなる。
            
    - 覚えるもの：
        
        - DNSアンプ攻撃の「アンプ」は、通信量の増幅。
            
        - 攻撃者が送る通信量より、攻撃対象に届く通信量の方が大きくなる。

-  トピック：用語整理
    
    - 何を扱った：
        
        - このスレッドで出た略語・英語
            
    - 結論：
        
        - DNS → Domain Name System → ディーエヌエス → ドメイン名とIPアドレスを対応付ける仕組み。
            
        - DDoS → Distributed Denial of Service → ディードス → 複数の通信元から攻撃対象に大量通信を送り、サービスを使えなくする攻撃。
            
        - reflection → リフレクション → 反射 → DNSサーバを反射板のように使って攻撃対象へ応答を返させること。
            
        - amplification → アンプリフィケーション → 増幅 → 小さい問い合わせを大きい応答にして通信量を増やすこと。
            
        - DNSSEC → DNS Security Extensions → ディーエヌエスセック → DNS応答に署名情報などが付き、応答サイズが大きくなる場合があるものとして触れた。
            
    - 覚えるもの：
        
        - reflection = 反射。
            
        - amplification = 増幅。
            
        - DNSリフレクションは「反射」。
            
        - DNSアンプは「増幅」。
