### 0. スレッド概要

- 扱ったテーマ：BASE特性、ACID特性との対比、分散データベースにおける可用性と整合性の考え方
    

### 1. 扱ったトピック一覧（時系列）

-  トピック：BASE特性とは何か
    
    - 何を扱った：
        
        - 「BASE特性ってなんですか？」という質問
            
        - BASE の略称と意味
            
        - ACID特性との対比
            
    - 結論：
        
        - BASE特性は、分散データベースで**強い整合性より、使い続けやすさ・応答性を優先する考え方**
            
        - BASE = **Basically Available → 基本的には使える → びっくりー あべいらぶる → 障害があっても全体として応答を返し続ける考え方**
            
        - BASE = **Soft state → 状態は固定ではない → そふと すてーと → レプリカ間で未同期など、一時的に状態が変わりうる**
            
        - BASE = **Eventual consistency → 最終的整合性 → いべんちゅある こんしすてんしー → 更新直後は不一致でも、しばらくすると揃う**
            
        - 具体例として、更新直後に
            
            - サーバーAでは新しい値が見える
                
            - サーバーBでは古い値が見える  
                という一時的不一致がありうるが、**後で揃えばよい**
                
        - ACID特性との対比として
            
            - **ACID**：正確さ・一貫性を強く重視、銀行取引のような処理向き
                
            - **BASE**：可用性・分散しやすさを重視、大規模Webサービス向き
                
        - ひとことでいうと、**「今この瞬間の完全一致より、止まらず使えることを優先する設計思想」**
            
    - 覚えるもの：
        
        - BASE = Basically Available / Soft state / Eventual consistency
            
        - Basically Available = 基本的には使える
            
        - Soft state = 状態は固定ではない
            
        - Eventual consistency = 最終的には整合する
            
        - BASEは**強い整合性より可用性・応答性を優先**
            
        - ACIDは**正確さ・一貫性を優先**、BASEは**可用性・分散性を優先**
