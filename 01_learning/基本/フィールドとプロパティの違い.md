### 0. スレッド概要

- 扱ったテーマ：
    
    - C#：public field（公開フィールド）とプロパティ（property）の違い
        
    - 設計方針：DTO/状態クラスをフィールドではなくプロパティにする理由（将来の変更耐性、事故防止）
        

---

### 1. 扱ったトピック一覧（時系列）

-  トピック：public field とプロパティの違いが分からない
    
    - 何を扱った：
        
        - 「フィールドは変数そのもの」「プロパティはアクセス用の窓口（get/set）」として整理
            
        - `public field` と `public { get; set; }` は見た目の使い方は似るが、プロパティは後から処理や制御を挟める点が異なる
            
        - サンプルとして `BackupState` を `public string RunDir { get; set; }` 等のプロパティにする案を提示された
            
    - 結論：
        
        - フィールド：公開すると “中身むき出し” で、後から制約や制御を追加しにくい
            
        - プロパティ：同じ呼び出し形（`obj.X = ...`）を保ったまま、後からトリム等の処理・バリデーション・アクセス制御を追加できる
            
        - 「公開する値はプロパティに寄せる」のが無難、という判断に至った
            
    - 覚えるもの：
        
        - 用語
            
            - Field → フィールド → （読み：フィールド）→ クラス内の変数そのもの
                
            - Property → プロパティ → （読み：プロパティ）→ get/set を持つアクセス窓口
                
            - get/set → ゲット／セット → 値の取得／設定
                
        - 最小セット（暗記）
            
            - 公開するメンバは基本プロパティ（`public X { get; set; }`）が無難
                
            - 「プロパティは後からロジックや制御を挟める」「フィールドは後から変更がつらい」
                
            - 読み取り専用化の例：`public bool Cleared { get; private set; }`（外から書けない形にできる）
