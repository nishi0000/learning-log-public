### 1. 扱ったトピック一覧（時系列）

-  トピック：設計規則の「副作用を持つことを禁止します」の意味
    
    - 何を扱った：
        
        - 1.2 設計規則にある「副作用を持つことを禁止します」が何を意味するかを確認
            
    - 結論：
        
        - 「その処理を呼び出したときに、戻り値以外のものを勝手に変えないでください」という意味で使われることが多い
            
        - 「呼んだだけで、戻り値以外の状態を勝手に変えるな」という理解で整理した
            
    - 覚えるもの：
        
        - 副作用禁止 ＝ 戻り値以外の状態を勝手に変えない
            
-  トピック：副作用の定義
    
    - 何を扱った：
        
        - プログラムにおける「副作用」とは何かを確認
            
    - 結論：
        
        - 計算結果を返す以外の影響を指す
            
        - 例として以下を挙げた
            
            - 変数の値を書き換える
                
            - DBを更新する
                
            - ファイルを書き換える
                
            - ログを出す
                
            - 画面表示する
                
            - 外部APIを呼ぶ
                
            - オブジェクトの中身を変更する
                
    - 覚えるもの：
        
        - 副作用 ＝ 戻り値以外の影響
            
-  トピック：副作用があるコード例
    
    - 何を扱った：
        
        - 外の変数を書き換える処理の例
            
    - 結論：
        
        - 以下の例は、副作用ありと整理した
            
            ```csharp
            int total = 0;
            
            int Add(int x)
            {
                total += x;
                return total;
            }
            ```
            
        - 理由：`Add(3)` を呼ぶと、戻り値を返すだけでなく外にある `total` の値も変わるため
            
    - 覚えるもの：
        
        - 外の変数を書き換える処理は副作用あり
            
-  トピック：副作用がないコード例
    
    - 何を扱った：
        
        - 引数から計算して結果だけ返す処理の例
            
    - 結論：
        
        - 以下の例は、副作用なしと整理した
            
            ```csharp
            int Add(int a, int b)
            {
                return a + b;
            }
            ```
            
        - 理由：外の状態を変えず、引数から計算して結果を返すだけだから
            
    - 覚えるもの：
        
        - 引数から計算して戻り値だけ返す処理は副作用なし
            
-  トピック：設計規則で副作用を禁止する意図
    
    - 何を扱った：
        
        - なぜ設計規則で副作用を禁止するのかを確認
            
    - 結論：
        
        - 「値を求めるだけの処理」と「更新する処理」を分けたい意図であることが多い
            
        - 副作用があると、以下の問題が起きやすいと整理した
            
            - 何が変わるのか分かりにくい
                
            - バグの原因を追いにくい
                
            - テストしにくい
                
            - 同じ入力でも結果が安定しない
                
            - 呼ぶだけで状態が変わるので怖い
                
    - 覚えるもの：
        
        - 計算・判定・変換の処理には副作用を入れない
            
        - 更新する処理は更新処理として分ける
            
-  トピック：getterっぽい処理なのに更新している例
    
    - 何を扱った：
        
        - `Get` という名前だが内部で状態更新している例
            
    - 結論：
        
        - 以下の例は分かりにくい副作用の例として整理した
            
            ```csharp
            User GetUser()
            {
                accessCount++;
                return _user;
            }
            ```
            
        - 理由：`Get` という名前なのに、呼んだだけで `accessCount` が増えるため
            
    - 覚えるもの：
        
        - 読み取り系の名前の処理で更新しない
            
-  トピック：チェック処理なのに保存している例
    
    - 何を扱った：
        
        - `Validate` の中で保存処理をしている例
            
    - 結論：
        
        - 以下の例は、判定処理に副作用が混ざっている例として整理した
            
            ```csharp
            bool Validate(Order order)
            {
                SaveLog(order);
                return order.Amount > 0;
            }
            ```
            
        - 理由：`Validate` は判定だけを期待しやすいが、呼ぶと保存も実行されるため
            
    - 覚えるもの：
        
        - 判定処理の中で保存処理をしない
            
-  トピック：引数でもらったオブジェクトを書き換える例
    
    - 何を扱った：
        
        - 引数で受け取ったオブジェクトの中身を変更する例
            
    - 結論：
        
        - 以下の例は、副作用ありと整理した
            
            ```csharp
            void FormatUser(User user)
            {
                user.Name = user.Name.Trim();
            }
            ```
            
        - 理由：呼び出し元から見ると、渡しただけなのに `user` の中身が変わるため
            
    - 覚えるもの：
        
        - 引数オブジェクトの中身変更も副作用
            
-  トピック：副作用を避ける書き方
    
    - 何を扱った：
        
        - 引数を書き換えず、新しい値を返す形の例
            
    - 結論：
        
        - 以下の例を、副作用を避ける書き方として整理した
            
            ```csharp
            string FormatName(string name)
            {
                return name.Trim();
            }
            ```
            
        - 入力を変えず、整形した結果を戻り値として返す形にしている
            
    - 覚えるもの：
        
        - 書き換えではなく、結果を返す形を優先する
            
-  トピック：更新処理は全部ダメなのか
    
    - 何を扱った：
        
        - 副作用禁止と、登録・更新・削除などの処理の関係
            
    - 結論：
        
        - 更新そのものが悪いわけではない
            
        - 以下のような処理は、そもそも副作用を起こすことが目的
            
            - 登録処理
                
            - 更新処理
                
            - 削除処理
                
            - ファイル出力
                
            - メール送信
                
        - したがって、この設計規則は
            
            - 計算・判定・変換のような処理には副作用を入れない
                
            - 更新系の処理は更新系として明示する  
                という意味で使われることが多いと整理した
                
    - 覚えるもの：
        
        - 更新処理は可
            
        - ただし、更新することを名前や役割で明示する
            
-  トピック：最終的に覚える整理
    
    - 何を扱った：
        
        - 副作用禁止の短い整理
            
    - 結論：
        
        - 読む処理 → 変えない
            
        - 計算する処理 → 変えない
            
        - 判定する処理 → 変えない
            
        - 更新する処理 → 更新することを名前や役割で明示する
            
    - 覚えるもの：
        
        - 「読む・計算・判定」は変えない
            
        - 「更新」は更新であることを明示する
