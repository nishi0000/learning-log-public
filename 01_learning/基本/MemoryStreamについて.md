### 1. 扱ったトピック一覧（時系列）

-  トピック：C#のMemoryStreamとは何か
    
    - 何を扱った：
        
        - MemoryStream の定義・用途のイメージ（「ファイルではなくメモリ上のデータを Stream として扱う」）
            
    - 結論：
        
        - MemoryStream は「メモリ上の byte列（byte[]）を Stream として読み書きできるもの」
            
        - “ファイルに書かない一時データ”を Stream API で扱う用途が多い、という整理
            
    - 覚えるもの：
        
        - MemoryStream = メモリ上の byte列を Stream として扱うクラス
            
-  トピック：Streamって何？
    
    - 何を扱った：
        
        - Stream の直感（“データの流れ/読み書き口”）と、ファイル・メモリ・ネットワーク等の違いを「同じ操作」で扱うという整理
            
    - 結論：
        
        - Stream は「byte列を先頭から順番に読み/書きするための共通の読み書き口」
            
        - “ファイルそのもの”ではなく、“読み書きの方法（インターフェース/概念）”寄り
            
    - 覚えるもの：
        
        - Stream = byte列を順番に扱うための共通の口（Read/Write/Copyの発想）
            
-  トピック：ファイル/バイト列がピンとこない
    
    - 何を扱った：
        
        - 「ファイル＝0と1で表せる？」という根本の確認
            
        - “ファイルはbyteの並び”という扱い方
            
    - 結論：
        
        - ファイルは最終的に 0/1 の並びで表現でき、実務上は「byteが並んだもの（byte列）」として扱う
            
    - 覚えるもの：
        
        - ファイル = byte列（byteがずらっと並ぶ）
            
-  トピック：byteとは何か
    
    - 何を扱った：
        
        - 0/1 と byte の関係（8ビット=1バイト）
            
        - “byteは0〜255の数として扱える”という感覚
            
    - 結論：
        
        - 0/1 が8個まとまった単位が 1 byte（1バイト）
            
        - byteは 0〜255 の値として扱える
            
    - 覚えるもの：
        
        - 1 byte = 8 bit
            
        - byte ≒ 0〜255 の数1個
            
-  トピック：文字コード（encoding）とは何か
    
    - 何を扱った：
        
        - “テキストもbyte列”という点
            
        - 文字 → byte列への変換ルールが文字コード（encoding）という整理
            
        - 文字数とbyte数が一致しない場合がある、という注意点
            
    - 結論：
        
        - 文字（テキスト）はそのまま保存されず、必ず byte列に変換されて保存される
            
        - その変換ルールが文字コード（encoding）
            
        - 文字コードがズレると文字化け、という因果関係の整理
            
    - 覚えるもの：
        
        - encoding = 文字 ↔ byte列 の変換ルール
            
        - 文字化け = 保存時と読取時の encoding 不一致
            
-  トピック：Streamは「ちょっとずつ扱う」概念か？
    
    - 何を扱った：
        
        - 「0と1（byte）の塊を丸ごとではなく、ちょっとずつ扱う概念がStream？」というユーザー理解の確認
            
        - “ちょっとずつ読む/書く”と“読み書き位置(Position)”の感覚
            
    - 結論：
        
        - Streamは byte列を順番に“少しずつ”読み書きするための仕組み、という理解でOK
            
        - 読む/書くと「位置」が進む（Position の直感が重要）
            
    - 覚えるもの：
        
        - Streamは「順番に少しずつ」扱う読み書き口
            
        - 読むと位置が進む（Positionの発想）
