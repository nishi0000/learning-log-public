### 1. 扱ったトピック一覧（時系列）

-  トピック：APOP
    
    - 何を扱った：
        
        - APOPとは何か
            
        - POP3でメールを受信するときの認証方式
            
    - 結論：
        
        - **APOP → Authenticated POP → エーポップ → POP3でメールを受信するときに、パスワードをそのまま送らずに認証する方式**
            
        - 通常のPOP3では、ユーザー名とパスワードを送る
            
        - 通信が暗号化されていない場合、通常のPOP3ではパスワードが盗み見られる危険がある
            
        - APOPでは、パスワードそのものではなく、サーバから送られてきた文字列とパスワードを使って作ったハッシュ値を送る
            
    - 覚えるもの：
        
        - **APOPは、POP3のパスワード盗聴対策用の認証方式**
            
        - **APOPは、パスワードをそのまま送らず、チャレンジ文字列とパスワードから作ったハッシュ値で認証する方式**
            
-  トピック：APOPの認証の流れ
    
    - 何を扱った：
        
        - APOPでどのように認証するか
            
    - 結論：
        
        - APOPの流れは以下。
            
            - メールサーバが、毎回異なる文字列をクライアントに送る
                
            - クライアントは、その文字列とパスワードを組み合わせる
                
            - それをハッシュ化する
                
            - ハッシュ値をサーバに送る
                
            - サーバも同じ計算をして、一致すれば認証成功
                
        - ネットワーク上にはパスワードそのものが流れない
            
    - 覚えるもの：
        
        - **サーバからの文字列 + パスワード → ハッシュ値**
            
        - **送るのはパスワードではなく計算結果**
            
-  トピック：APOPの注意点
    
    - 何を扱った：
        
        - APOPが現在でも強い方式なのか
            
    - 結論：
        
        - APOPは、パスワードを平文で送らない点では通常のPOP3より安全
            
        - ただし、現在ではあまり強い方式とは言えない
            
        - 理由は、APOPでは主にMD5という古いハッシュ関数が使われるため
            
        - 現在は、APOPよりもPOP3 over SSL/TLSのように通信経路そのものを暗号化する方式が一般的
            
    - 覚えるもの：
        
        - **APOPは平文パスワード送信を避ける方式**
            
        - **現在はPOP3 over SSL/TLSのように通信路を暗号化する方式が一般的**
            
-  トピック：チャレンジレスポンス認証
    
    - 何を扱った：
        
        - チャレンジレスポンス認証とは何か
            
    - 結論：
        
        - チャレンジレスポンス認証は、パスワードそのものを送らずに本人確認する認証方式
            
        - サーバが毎回変わる「お題」を出す
            
        - このお題が「チャレンジ」
            
        - クライアントは、そのお題と自分のパスワードを使って計算する
            
        - クライアントが返す計算結果が「レスポンス」
            
    - 覚えるもの：
        
        - **チャレンジレスポンス認証 = サーバからの使い捨ての値と秘密情報を使って応答を作り、パスワードを直接送らずに認証する方式**
            
        - **チャレンジ = サーバから出されるお題**
            
        - **レスポンス = クライアントが返す計算結果**
            
-  トピック：チャレンジレスポンス認証の流れ
    
    - 何を扱った：
        
        - チャレンジレスポンス認証の処理手順
            
    - 結論：
        
        - 流れは以下。
            
            - サーバがランダムな文字列を送る
                
            - クライアントが「ランダム文字列 + パスワード」を使ってハッシュ値を作る
                
            - クライアントがハッシュ値を送る
                
            - サーバも同じ計算をする
                
            - 結果が一致したら認証成功
                
    - 覚えるもの：
        
        - **サーバがチャレンジを出す**
            
        - **クライアントがパスワードを使ってレスポンスを作る**
            
        - **サーバ側でも同じ計算をして一致確認する**
            
-  トピック：チャレンジレスポンス認証の利点
    
    - 何を扱った：
        
        - チャレンジレスポンス認証で何が安全になるか
            
    - 結論：
        
        - パスワードそのものが通信経路に流れない
            
        - 盗聴されても見えるのはパスワードではなく計算結果
            
        - チャレンジは毎回変わる
            
        - 前回のレスポンスを盗んでそのまま使うリプレイ攻撃をしにくくする
            
    - 覚えるもの：
        
        - **パスワードを直接送らない**
            
        - **毎回変わるチャレンジを使う**
            
        - **リプレイ攻撃をしにくくする**
            
-  トピック：APOPとチャレンジレスポンス認証の関係
    
    - 何を扱った：
        
        - APOPとチャレンジレスポンス認証のつながり
            
    - 結論：
        
        - APOPはチャレンジレスポンス認証を使っている
            
        - APOPは、POP3で使うチャレンジレスポンス認証方式
            
    - 覚えるもの：
        
        - **APOP = POP3で使うチャレンジレスポンス認証方式**
